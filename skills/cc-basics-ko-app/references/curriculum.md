## 레슨 1. Claude Code와 첫 대화

**목표**: Claude Code가 무엇인지 알고, 프로젝트 폴더에서 켜서 질문하고 끌 수 있다.

핵심 개념
- Claude Code = 터미널(글자로 컴퓨터에 명령하는 창)에서 쓰는 AI 도우미. 내 폴더의 파일을 읽고, 고치고, 명령을 실행할 수 있다. 그래서 "어느 폴더에서 켜느냐"가 중요하다.
- 켜기: 작업할 폴더로 이동(`cd 폴더이름`) 후 `claude` 입력.
- 그냥 한국어로 말하듯 요청하면 된다. 정해진 문법이 없다.
- 끄기: `/exit` 또는 `Ctrl+D` 두 번.
- 막히면 `/help`.

실습
1. 연습용 폴더를 만들고 그 안에서 Claude Code를 켜기:
   ```bash
   mkdir claude-practice
   cd claude-practice
   claude
   ```
2. "이 폴더에 hello.txt 파일을 만들고 '안녕하세요'라고 써줘"라고 요청 → 권한 요청이 뜨면 내용을 읽고 허용. (최신 버전은 auto 모드로 시작해서 확인 창 없이 바로 만들어질 수도 있다. 그래도 정상이며 레슨 4에서 다룬다.)
3. "방금 만든 파일 내용을 보여줘"라고 요청.
4. `/help`를 입력해 보고, `/exit`로 종료.

확인 포인트: 화면 아래 상태 표시줄에 어떤 모드가 보이는지, 허락을 구하는 창이 떴는지 물어본다(레슨 4 복선).

퀴즈 문제 은행
- Q. Claude Code가 내 파일을 읽고 고칠 수 있는 범위를 정하는 가장 기본적인 요소는? ① 인터넷 속도 ② Claude Code를 켠 폴더 ③ 모니터 크기 ④ 키보드 언어 → 정답 ②
- Q. Claude Code에게 요청할 때 올바른 방법은? ① 정해진 영어 명령어만 써야 한다 ② 평소 말하듯 한국어로 요청해도 된다 ③ 반드시 코드로만 말해야 한다 ④ 질문은 한 단어만 → 정답 ②
- Q. Claude Code를 종료하는 명령은? ① `/clear` ② `/exit` ③ `/init` ④ `/model` → 정답 ②

## 레슨 2. 입력 기호와 단축키

**목표**: `/`, `!`, `@`의 차이를 알고 기본 단축키를 쓸 수 있다.

핵심 개념
- `/` = Claude Code에게 내리는 "기능 명령". `/`만 치면 목록이 뜬다.
- `!` = Claude를 거치지 않고 터미널 명령을 직접 실행. 결과는 대화에 남아 Claude가 참고한다. 예: `! ls`
- `@` = 파일 가리키기. 예: `@hello.txt 이 파일을 영어로 번역해줘`
- `Esc` = Claude가 엉뚱한 방향으로 갈 때 멈추기. 멈춘 뒤 다시 지시하면 된다.
- `↑` = 이전에 쓴 입력 다시 불러오기.
- 여러 줄 입력: `\` 다음 `Enter`, 또는 `Shift+Enter`(대부분의 터미널).
- `?` (빈 입력에서) = 단축키 도움말.

실습
1. `/`만 입력해서 명령 목록 둘러보기, `/cl`까지 쳐서 걸러지는 것 보기.
2. `! ls`로 폴더 파일 목록 보기.
3. `@hello.txt 이 문장을 존댓말·반말 두 가지로 바꿔줘` 요청.
4. 긴 작업을 시킨 뒤("1부터 100까지 숫자마다 설명을 써줘") 바로 `Esc`로 멈춰 보기.

퀴즈 문제 은행
- Q. Claude에게 묻지 않고 `ls` 명령을 직접 실행하려면? ① `/ls` ② `! ls` ③ `@ls` ④ `# ls` → 정답 ②
- Q. 특정 파일을 콕 집어 Claude에게 알려주는 기호는? ① `@` ② `!` ③ `/` ④ `?` → 정답 ①
- Q. Claude가 잘못된 방향으로 작업하고 있다. 가장 먼저 누를 키는? ① `Shift+Tab` ② `Esc` ③ `Ctrl+L` ④ `↑` → 정답 ②
- Q. 방금 보낸 긴 질문을 조금만 고쳐 다시 보내고 싶다면? ① 처음부터 다시 타이핑 ② `↑`로 불러와 수정 ③ `/clear` ④ 종료 후 재시작 → 정답 ②

## 레슨 3. 대화 관리 명령

**목표**: 대화가 길어지거나 주제가 바뀔 때 알맞은 명령을 고를 수 있다.

핵심 개념
- 컨텍스트 = Claude가 지금 기억하고 있는 대화 내용. 공간이 한정되어 있어, 너무 길어지면 앞 내용이 흐려지거나 느려진다.
- `/context` = 지금 공간을 얼마나 썼는지 보기.
- `/clear` = 새 노트 펼치기. 완전히 다른 작업을 시작할 때. (이전 대화는 `/resume`으로 다시 열 수 있음)
- `/compact` = 지금까지를 요약 메모로 정리하고 같은 작업을 이어감. `/compact 로그인 기능 위주로 요약해줘`처럼 지시 가능.
- `/resume` = 어제 하던 대화 다시 열기.
- `/rewind` (또는 빈 입력에서 `Esc` 두 번) = 이전 시점으로 되감기. 대화와 코드 변경을 되돌릴 수 있다.

판단 기준(학습자에게 표로 보여주기 좋음)
| 상황 | 명령 |
|---|---|
| 같은 작업인데 대화가 너무 길다 | `/compact` |
| 전혀 다른 작업을 시작한다 | `/clear` |
| 어제 하던 대화를 이어가고 싶다 | `/resume` |
| Claude가 방금 한 변경을 되돌리고 싶다 | `/rewind` |
| 공간이 얼마나 남았는지 궁금하다 | `/context` |

실습
1. `/context`로 현재 사용량 보기.
2. 몇 가지 대화를 한 뒤 `/compact`, 이어서 "아까 무슨 얘기 했지?"라고 물어 요약이 남아 있는지 확인.
3. `/clear` 후 같은 질문을 해 보고 차이 비교.
4. `/resume`으로 이전 대화 다시 열기.

퀴즈 문제 은행
- Q. 같은 기능을 계속 만드는 중인데 대화가 너무 길어졌다. 흐름은 유지하고 싶다면? ① `/clear` ② `/compact` ③ `/exit` ④ `/init` → 정답 ②
- Q. 버그 수정을 끝내고 전혀 다른 문서 작업을 시작한다면? ① `/clear` ② `/compact` ③ `/rewind` ④ `/memory` → 정답 ①
- Q. Claude가 파일을 잘못 고쳤다. 고치기 전 상태로 돌아가려면? ① `/clear` ② `/rewind` ③ `/context` ④ `/status` → 정답 ②
- Q. `/clear`를 하면 이전 대화는? ① 영원히 사라진다 ② `/resume`으로 다시 열 수 있다 ③ CLAUDE.md에 저장된다 ④ 자동으로 요약된다 → 정답 ②

## 레슨 4. 권한과 모드

**목표**: 권한 요청을 읽고 판단할 수 있고, 권한 모드를 바꿀 수 있다.

핵심 개념
- Claude는 파일 수정이나 명령 실행 전에 허락을 구할 수 있다. 이것은 안전장치다. 무엇을 하려는지 읽고 판단하는 습관이 중요하다.
- 지금 어떤 모드인지는 화면 아래 상태 표시줄에 보인다. 최신 버전은 기본적으로 `auto` 모드(`⏵⏵ auto mode on`)로 시작한다. 검사 모델이 대신 검토해서 일상적인 확인 창을 건너뛰기 때문에, 권한 요청이 잘 안 보일 수 있다.
- 선택지: 이번만 허용 / 허용하고 다시 묻지 않기("Yes, and don't ask again" → `.claude/settings.local.json`에 규칙 저장) / 거부.
- `Shift+Tab`으로 모드 전환:
  - Manual(`⏸ manual mode on`): 매번 물어봄. 권한 요청을 직접 보며 배우기 좋다
  - `acceptEdits`: 파일 수정은 바로 적용
  - `plan`: 먼저 계획만 세워 보여줌. 큰 작업 전에 유용. `/plan 할일`로 바로 시작도 가능
  - `auto`: 검사 모델이 대신 검토. 편하지만 안전을 보장하지는 않으니, 중요한 폴더에서는 결과를 꼭 확인한다
- `/permissions` = 지금까지 허용/거부한 규칙 보기·관리.
- 묻지 않고 다 진행하는 `bypassPermissions` 모드도 있지만 초보자에게는 권하지 않는다.

실습
1. 상태 표시줄에서 지금 모드를 확인하고, `Shift+Tab`으로 Manual(`⏸ manual mode on`)로 바꾸기.
1-1. "hello.txt를 지워줘"라고 요청 → 권한 요청에서 **거부** 선택해 보기.
2. `Shift+Tab`을 눌러 화면 아래 모드 표시가 바뀌는 것 확인, `plan` 모드에서 "간단한 할 일 목록 웹페이지를 만들어줘" 요청해 계획만 받아보기.
3. 다시 Manual 모드로 돌아오기. 원래 모드(auto 등)로 쓸지는 학습자가 고르게 한다.
4. `/permissions` 열어 보기.

퀴즈 문제 은행
- Q. 큰 작업을 시키기 전에 Claude가 어떻게 할지 먼저 보고 싶다면? ① `acceptEdits` 모드 ② `plan` 모드 ③ `/clear` ④ `/compact` → 정답 ②
- Q. 권한 요청에서 "Yes, and don't ask again"을 고르면 규칙이 저장되는 곳은? ① `CLAUDE.md` ② `.claude/settings.local.json` ③ `README.md` ④ 저장되지 않는다 → 정답 ②
- Q. 초보자에게 가장 안전한 사용 습관은? ① 모든 요청을 무조건 허용 ② 요청 내용을 읽고 판단해서 허용 ③ 항상 거부 ④ 권한 요청을 끄기 → 정답 ②
- Q. 권한 모드를 바꾸는 단축키는? ① `Ctrl+C` ② `Shift+Tab` ③ `Esc` ④ `Ctrl+R` → 정답 ②
- Q. 파일을 만들었는데 확인 창이 안 떴다. 화면 아래에 `⏵⏵ auto mode on`이 보인다면? ① 고장이다 ② 검사 모델이 대신 검토하는 auto 모드라서 ③ 파일이 안 만들어졌다 ④ 인터넷이 끊겼다 → 정답 ②

## 레슨 5. CLAUDE.md로 Claude에게 프로젝트 알려주기

**목표**: CLAUDE.md의 역할과 위치를 알고, 직접 만들고 고칠 수 있다.

핵심 개념
- Claude는 매 세션을 "처음 만난 사람"처럼 시작한다. CLAUDE.md는 매번 시작할 때 읽는 안내 메모다. 예: 실행 방법, 테스트 방법, 코딩 규칙, "답변은 한국어로".
- 위치 3종: `~/.claude/CLAUDE.md`(나의 모든 프로젝트), `./CLAUDE.md`(이 프로젝트, 팀과 공유), `./CLAUDE.local.md`(이 프로젝트, 나만).
- 여러 개가 있으면 모두 합쳐서 읽는다.
- 만드는 법: `/init`(자동 초안), 또는 직접 작성, 또는 Claude에게 "CLAUDE.md에 ~를 추가해줘".
- 고치는 법: `/memory`로 열기.
- 다른 파일 포함: `@README.md`처럼 쓰면 그 파일도 함께 읽음.
- 잘 쓰는 법: 짧고 구체적으로. "코드를 깔끔하게"보다 "들여쓰기 2칸".
- 참고: Claude가 스스로 메모를 남기는 자동 메모리도 있다(`/memory`에서 켜고 끔).

실습
1. 연습 폴더에서 `/init` 실행 → 생성된 CLAUDE.md 내용 읽어보기.
2. `/memory`로 열어 "- 답변은 항상 한국어로, 짧게" 한 줄 추가.
3. `/clear` 후 아무 질문이나 해서 지침이 반영되는지 확인.
4. `/context`에서 Memory files에 CLAUDE.md가 보이는지 확인.

퀴즈 문제 은행
- Q. 모든 프로젝트에서 "답변은 한국어로"를 적용하고 싶다면 어디에 쓸까? ① `./CLAUDE.md` ② `~/.claude/CLAUDE.md` ③ `./CLAUDE.local.md` ④ `.claude/settings.json` → 정답 ②
- Q. 팀원과 공유하지 않고 이 프로젝트에서 나만 쓰는 지침은? ① `./CLAUDE.local.md` ② `./CLAUDE.md` ③ `~/.claude/CLAUDE.md` ④ `README.md` → 정답 ①
- Q. 프로젝트를 분석해 CLAUDE.md 초안을 만들어 주는 명령은? ① `/memory` ② `/init` ③ `/config` ④ `/compact` → 정답 ②
- Q. CLAUDE.md 지침이 더 잘 지켜지게 하려면? ① 길고 추상적으로 ② 짧고 구체적으로 ③ 영어로만 ④ 대문자로만 → 정답 ②
- Q. CLAUDE.md 안에서 README.md 내용도 함께 읽게 하려면? ① `#README.md` ② `@README.md` ③ `!README.md` ④ `/README.md` → 정답 ②

## 레슨 6. settings.json으로 설정하기

**목표**: 설정 파일 위치와 우선순위를 알고, 간단한 권한 규칙을 작성할 수 있다.

핵심 개념
- CLAUDE.md는 "부탁(지침)", settings.json은 "규칙(설정)". 예: 어떤 명령을 묻지 않고 허용할지, 어떤 파일은 절대 읽지 못하게 할지.
- 쉬운 방법부터: `/config`로 테마 등 바꾸기 → Claude Code가 알아서 파일에 저장.
- 파일 위치: `~/.claude/settings.json`(나·모든 프로젝트), `.claude/settings.json`(팀 공유), `.claude/settings.local.json`(나·이 프로젝트), 관리형(회사).
- 우선순위: 관리형 > 명령줄 > 프로젝트 로컬 > 공유 프로젝트 > 사용자. 단 allow/deny 같은 목록은 합쳐진다.
- JSON 주의: 주석(`//`)과 마지막 쉼표 금지. 틀리면 시작할 때 Settings Error가 뜬다.
- 확인: `/status`의 Setting sources.
- 좋은 습관: 비밀 정보가 담긴 `.env`는 `deny`로 막기.
- CLAUDE.md와 settings.json 비교: CLAUDE.md는 Claude가 참고하는 맥락이고 강제가 아님 / settings.json의 deny는 실제로 막는다.

실습
1. `/config`에서 테마 바꿔 보기.
2. 연습 폴더에 `.claude/settings.json`을 Claude에게 만들어 달라고 요청: "`.env` 파일은 읽지 못하게 하고 `ls` 명령은 묻지 않게 하는 settings.json을 만들어줘". 만들어진 내용을 함께 읽고 각 줄의 의미 설명.
3. `/status`로 Setting sources 확인, `/permissions`에서 규칙 확인.
4. (선택) 일부러 마지막 쉼표를 넣어 오류가 어떻게 보이는지 확인 후 고치기.

퀴즈 문제 은행
- Q. 팀 전체가 같은 권한 규칙을 쓰게 하려면 어디에 두고 git에 커밋할까? ① `~/.claude/settings.json` ② `.claude/settings.json` ③ `.claude/settings.local.json` ④ `CLAUDE.local.md` → 정답 ②
- Q. 팀 설정은 `true`, 내 `.claude/settings.local.json`은 `false`. 이 프로젝트에서 나에게 적용되는 값은? ① `true` ② `false` ③ 오류 ④ 랜덤 → 정답 ② (프로젝트 로컬 > 공유 프로젝트)
- Q. 다음 중 settings.json에서 오류가 나는 것은? ① 키를 큰따옴표로 감싸기 ② 마지막 항목 뒤에 쉼표 ③ 배열 사용 ④ 중괄호로 시작 → 정답 ②
- Q. `.env` 파일을 Claude가 절대 읽지 못하게 확실히 막으려면? ① CLAUDE.md에 "읽지 마" 쓰기 ② settings.json의 `deny`에 `Read(./.env)` 추가 ③ `/clear` ④ `/compact` → 정답 ②
- Q. 어떤 설정 파일이 로드됐는지 확인하는 명령은? ① `/status` ② `/init` ③ `/rewind` ④ `/resume` → 정답 ①

## 졸업 과제

빈 연습 폴더에서 아래를 혼자 해 보게 하고, 막히는 단계만 도와준다.
1. Claude Code를 켜고 `plan` 모드에서 "간단한 자기소개 HTML 페이지" 계획 받기
2. Manual 모드로 바꿔 계획대로 만들게 하고, 권한 요청을 읽고 허용
3. `/init`으로 CLAUDE.md 만들고 "답변은 한국어로" 추가
4. `.claude/settings.json`에 `.env` 읽기 금지 규칙 추가, `/status`로 확인
5. `/compact` 후 "지금까지 한 일을 정리해줘"
6. `/exit`로 종료

마친 뒤 6개 레슨을 섞은 종합 퀴즈 5문제로 마무리한다. 4문제 이상 맞히면 수료로 보고, SKILL.md의 '수료와 다음 단계'에 따라 중급 과정을 소개한다. 3문제 이하라면 틀린 레슨을 짧게 복습한 뒤 다시 퀴즈를 낸다.
